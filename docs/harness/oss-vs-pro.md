# 無料の OSS 版と、このハーネスの違い

## 先に、正直な開示

**同種のものが無料で手に入ります。**

- Claude Code の skill マーケットプレイスには、2026 年 1 月時点で
  [96,751 件の skill が無料で公開](https://qiita.com/emi_ndk/items/a299ccefae53ab9ea1d8)されています
- 弊社自身も [willink-claude-kit](https://github.com/willink-oss/willink-claude-kit)（MIT）で
  **17 本の skill を無料公開**しています。うち `judge-rubric-vote` `live-state-verify-guard`
  `maker-checker-relay` `adversarial-refute-vote` `commit-convention-gate` などは、
  このハーネスと**同じ設計思想の同じ系譜**です
- 同梱の `goal-loop.sh` は、**機能的に等価なものが上記 MIT リポジトリにあります**
  （こちらは日本語版 + 9 ケースの self-test 付き。原型は同一）

先にこれを書くのは、後で気づかれるより先に言った方がいいからです。
その上で、**何が違うのか**を以下に書きます。

---

## 3 つの違い

### 違い 1 — 単体の skill ではなく、束と配線

OSS 版は「便利な skill が 17 本ある」状態です。個別に取ってきて、
自分のリポジトリに合わせて配線するのは購入者の仕事になります。

このハーネスは、**26 の skill + 13 のエンジン + 配線手順 + 検証コマンド**が
1 つの整合した束になっています。skill 間の相互参照（101 件）はすべて実在を検査済みで、
`verify.sh` が dangling 0 を毎回実測します。

| | 無料 OSS 版 | このハーネス |
|---|---|---|
| skill 本数 | 17（個別） | 26（束・相互参照検査済み） |
| エンジン | skill 側で参照 | **13 本同梱**（6,900 行・自己完結） |
| 依存 | リポジトリ構成に依存 | Python3 標準ライブラリ / POSIX shell のみ・**ネットワーク不要** |
| 検証 | skill による | **13/13 が `--self-test` を持つ**（hermetic） |
| 一括検証 | なし | **`./verify.sh` で 17 検査を 1 コマンド** |
| 配線 | 手動 | `install.sh` |

### 違い 2 — 閾値の根拠が同梱されている

ここが本体です。

検査ロジック自体は、公開情報から書けます。「コミットメッセージを採点する」
「出典リンクの充足率を測る」——アイデアとしては誰でも思いつきます。

**再構成できないのは「なぜその検査軸なのか」です。**

同梱の [`incidents.md`](incidents.md) は、2026-03 から 2026-08 までの実運用
（1 人 + AI エージェント体制・コミット約 3,900 件）で起きた事故のうち、
**ゲート化に至ったものの台帳**です。20 件を超える事故が、
**症状 / 構造 / 教訓** の 3 点で記録されています。例:

- lint ゲートが導入以来 1 ヶ月間**一度も実行されないまま緑**を返していた（原因は環境変数 1 行）
- フィルタの単数複数の取り違えで、**98 件を「0 件」と数週間報告し続けた**
- 一回きりの見積が要約を 5 層経て「日次の恒常的な事実」に化け、公開物に到達した
- 「ガードが止めてくれるはず」を前提にしたテストが、**本番に書き込んだ**

これらは机上のリスク列挙ではなく、**実際に起きて、実際に直したもの**です。
各ゲートの検査軸と終了コード規約は、ここから逆算されています。

同じものを持とうとすると、5 ヶ月ぶんの事故が必要になります。

### 違い 3 — 製品が自分を証明する

```bash
./verify.sh
```

このコマンドが exit 0 を返さない限り、このハーネスは出荷されません。
検査するのは:

1. **13 本すべての `--self-test` が exit 0**（skip は成功として数えない）
2. **skill 内部参照 101 件すべてが実在**（dangling 0）
3. **配布元固有の識別子が 0 件**（ホームパス・社名・内部パス）
4. **26 本すべてに frontmatter**
5. **ネットワーク呼び出し 0 件**（オフラインで完結）

すべてのカウントに**分母が付いています**。「0 件」と「そもそも走査していない」を
区別できない出力は、このハーネス自身の原則違反だからです
（[`incidents.md` A-2](incidents.md)）。

## 買う前に確かめてほしいこと

参考にした[記事](https://note.com/masa_wunder/n/nda5dfb0c69a8)が挙げていた
「買う前の 3 つの問い」に、こちらから答えます。

**Q. ワンショットプロンプトで再現できないか？**

個々の検査の**アイデア**は再現できます。再現できないのは
「同じ入力 → 同じ出力」の決定論性と、それを保証する self-test です。
プロンプトは実行のたびに違う答えを返すので、**回帰の検知には使えません**。
ゲートの価値は賢さではなく、**同じであること**にあります。

**Q. 作者がハーネス全体を設計しているか？**

しています。同梱の 3 原則（[`principles.md`](principles.md)）は、
承認境界・停止判定・自己申告の扱いを 1 つの体系にしたものです。
運用実体は、フック 17 本・スクリプト 83 本・ADR 33 本・約 3,900 コミットです。

**Q. 中身が一般知識の整形ではないか？**

[`incidents.md`](incidents.md) を先に読んでください。
一般知識から書けるものが 1 つでもあれば、その分は無料 OSS 版で足ります。

## 買わない方がいい場合

- **エージェントを本格運用していない** — ゲートは事故が起きて初めて価値が出ます。
  事故が無いうちは、ただの実行時間です
- **1 リポジトリ・1 人・短期の作業** — 束の管理コストが効果を上回ります
- **無料版で足りている** — [willink-claude-kit](https://github.com/willink-oss/willink-claude-kit)
  を先に試してください。そこで足りないと感じたときが、こちらの出番です
